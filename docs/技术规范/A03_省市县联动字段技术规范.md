# 省市县三级联动字段技术规范

> 文档版本：1.4 | 创建：2026-03-18 | 更新：2026-07-22

## 1. 概述

### 1.1 系统目标
为中国行政区划（省-市-区）提供三级联动选择能力，支持在表单中快速选择地区，数据存储为 JSON 格式。

### 1.2 数据来源
- **主数据源**：https://github.com/modood/Administrative-divisions-of-China
- **数据格式**：pca-code.json（省市区三级联动数据）
- **数据量**：31 省份、342 城市、3056 区县
- **本地文件**：`core/data/china_regions.json`

### 1.3 技术选型
- **后端**：Django 6.0 | **前端**：原生 JS + Bootstrap 5 | **数据**：独立 DB 表 | **API**：RESTful JSON

## 2. 系统架构
四层架构：前端展示层 → API 接口层 → 业务服务层 (ChinaRegionService) → 数据模型层 (ChinaRegion)

## 3. 数据模型

### 3.1 ChinaRegion 模型
**文件**：`core/models.py`

| 字段 | 类型 | 说明 |
|------|------|------|
| code | CharField(max_length=6, unique=True) | 行政区划代码，如 440305 |
| name | CharField(max_length=100) | 地区名称，如 "南山区" |
| level | IntegerField(choices=LEVEL_CHOICES, db_index=True) | 1=省/直辖市, 2=市, 3=区/县 |
| parent | ForeignKey("self", on_delete=models.PROTECT, null=True, blank=True, related_name="children") | 自关联，指向父级地区 |
| created_at | DateTimeField(auto_now_add=True) | 创建时间 |

### 3.2 层级关系
code 前缀匹配：省(2位) → 市(4位, parent=省code) → 区(6位, parent=市code)

## 4. 服务层

### 4.1 ChinaRegionService
**文件**：`core/services/china_region_service.py`

| 方法 | 说明 | 返回值 |
|------|------|--------|
| `import_from_file(file_path)` | 从本地 JSON 文件导入数据 | `{'success': True, 'count': 3429, 'provinces': 31, 'cities': 342, 'districts': 3056}` |
| `import_from_url(url)` | 从网络导入数据（自动重试备用源） | `{'success': True, 'count': 3429, 'provinces': 31, 'cities': 342, 'districts': 3056}` |
| `download_to_file(url)` | 从网络下载数据保存到本地文件 | `{'success': True, 'message': '...', 'file_path': '...'}` |
| `get_provinces()` | 获取所有省份 | `List[ChinaRegion]` |
| `get_cities(province_code)` | 获取省份下的所有城市 | `List[ChinaRegion]` |
| `get_districts(city_code)` | 获取城市下的所有区县 | `List[ChinaRegion]` |
| `get_by_code(code)` | 根据行政区划代码获取 | `ChinaRegion \| None` |
| `get_tree()` | 获取完整树形结构 | `List[Dict]` |
| `search(keyword)` | 搜索地区 | `List[ChinaRegion]` |
| `get_full_path(code)` | 获取完整路径 | `"广东省 - 深圳市 - 南山区"` |
| `get_stats()` | 获取统计信息 | `{'total': 3429, 'provinces': 31, 'cities': 342, 'districts': 3056}` |

### 4.2 数据导入优化
使用 `bulk_create` 分三批（省→市→区）在 `transaction.atomic()` 内导入，共 3429 条。

## 5. API 接口

### 5.1 接口列表

| 接口 | 方法 | 参数 | 说明 |
|------|------|------|------|
| `/api/v1/regions/provinces/` | GET | - | 获取所有省份 |
| `/api/v1/regions/cities/` | GET | `province` | 获取指定省份的城市 |
| `/api/v1/regions/districts/` | GET | `city` | 获取指定城市的区县 |
| `/api/v1/regions/search/` | GET | `q` | 搜索地区 |
| `/api/v1/regions/path/` | GET | `code` | 获取完整路径 |
| `/api/v1/regions/stats/` | GET | - | 获取统计信息 |

### 5.2 响应格式
统一格式：`{success: true, data: [...]}`

## 12. 数据维护流程

### 12.1 数据架构
GitHub 源 → 本地 JSON (`core/data/china_regions.json`) → 数据库 (ChinaRegion)

### 12.2 初始化流程
`init_db.py --with-data` → `ChinaRegionService.import_from_file()` → `bulk_create` 写入 3429 条

### 12.3 维护更新
`./run.sh` 菜单选项 5：下载/更新省市区数据

## 13. 故障排除

### 13.1 网络超时
自动尝试 ghproxy、gitee 备用镜像，全部失败则手动下载替换 `china_regions.json` 后重新导入。

### 13.2 数据不一致
```bash
./venv/bin/python -c "from core.services.china_region_service import ChinaRegionService; print(ChinaRegionService.import_from_file())"
```

### 13.3 初始化后无数据
```bash
./run.sh 3 → 5
```
