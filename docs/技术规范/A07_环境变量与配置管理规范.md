# 环境变量与配置管理规范

> 文档版本：1.0  
> 创建日期：2026-05-02  
> 适用范围：cimf_django/settings.py、config.env、config.env.sample

---

## 一、概述

### 1.1 目的

本规范定义 CIMF 项目中环境变量和配置文件的管理标准，实现：
- 开发/生产环境配置分离
- 敏感信息不进入版本控制
- 配置项有清晰的文档说明
- 便于部署和运维

### 1.2 配置文件结构

```
cimf/
├── config.env              # 实际配置文件（不提交到Git）
├── config.env.sample      # 配置模板（提交到Git）
├── cimf_django/
│   └── settings.py       # Django配置（从环境变量读取）
└── docs/
    └── 技术规范/
        └── A07_环境变量与配置管理规范.md（本文件）
```

## 二、环境变量命名规范

### 2.1 命名规则

| 规则 | 说明 | 示例 |
|------|------|------|
| **前缀** | 使用 `DJANGO_` 作为 Django 配置前缀 | `DJANGO_DEBUG` |
| **大写** | 全部使用大写字母 | `DJANGO_SECRET_KEY` |
| **下划线** | 使用下划线分隔单词 | `DJANGO_ALLOWED_HOSTS` |
| **描述性** | 变量名应清晰描述用途 | `DJANGO_HSTS_SECONDS` |

### 2.2 变量分类

#### 核心配置
| 变量名 | 说明 | 默认值 | 必填 |
|--------|------|--------|------|
| `DJANGO_SECRET_KEY` | Django 密钥（50+字符） | `secrets.token_urlsafe(50)`（自动生成） | ⚠️ |
| `DJANGO_DEBUG` | 调试模式（True/False） | `True` | ❌ |
| `DJANGO_ENV` | 环境标识（development/production） | `development` | ❌ |
| `DJANGO_ALLOWED_HOSTS` | 允许访问的主机（逗号分隔） | `localhost,127.0.0.1` | ❌ |

#### 开发服务器配置
| 变量名 | 说明 | 默认值 | 必填 |
|--------|------|--------|------|
| `DJANGO_PORT` | 开发服务器端口（`server_service.py` 和 `manage.py` 中使用） | `8000` | ❌ |
| `DJANGO_HOST` | 开发服务器绑定地址（`server_service.py` 和 `manage.py` 中使用） | `0.0.0.0` | ❌ |

#### 安全配置（生产环境）
| 变量名 | 说明 | 默认值 | 必填（生产） |
|--------|------|--------|--------------|
| `DJANGO_HSTS_SECONDS` | HSTS 过期时间（秒） | `0` | ✅ |
| `DJANGO_HSTS_INCLUDE_SUBDOMAINS` | HSTS 包含子域名 | `false` | ❌ |
| `DJANGO_HSTS_PRELOAD` | HSTS 预加载 | `false` | ❌ |
| `DJANGO_SSL_REDIRECT` | 强制 HTTPS 重定向 | `false` | ✅ |
| `DJANGO_SESSION_COOKIE_SECURE` | Session Cookie HTTPS | `false` | ✅ |
| `DJANGO_CSRF_COOKIE_SECURE` | CSRF Cookie HTTPS | `false` | ✅ |
| `DJANGO_BEHIND_PROXY` | 是否部署在反向代理之后 | `false` | ❌ |
| `DJANGO_CSRF_TRUSTED_ORIGINS` | CSRF 可信来源域名（逗号分隔） | - | 有代理时推荐 |

#### 数据库配置
| 变量名 | 说明 | 默认值 | 必填 |
|--------|------|--------|------|
| `DJANGO_DB_TYPE` | 数据库类型（sqlite/mysql） | `sqlite` | ❌ |
| `DJANGO_DB_NAME` | 数据库名称 | `django.db`(sqlite，位于 `instance/` 子目录) / `cimf`(mysql) | ❌ |
| `DJANGO_DB_USER` | 数据库用户 | - | MySQL必填 |
| `DJANGO_DB_PASSWORD` | 数据库密码 | - | MySQL必填 |
| `DJANGO_DB_HOST` | 数据库主机 | `localhost` | ❌ |
| `DJANGO_DB_PORT` | 数据库端口 | `3306` | ❌ |

#### 访问控制
| 变量名 | 说明 | 默认值 | 必填 |
|--------|------|--------|------|
| `DJANGO_IP_RESTRICTION_ENABLED` | 是否启用IP限制 | `false` | ❌ |
| `DJANGO_IP_WHITELIST` | IP白名单（逗号分隔） | `127.0.0.1` | IP限制时必填 |

## 三、config.env.sample 规范

### 3.1 文件结构

```bash
# ============================================
# CIMF 管理系统配置文件模板
# ============================================

# ----- 配置分组 -----
VARIABLE_NAME=default_value  # 简短说明
```

### 3.2 注释规范

| 注释类型 | 格式 | 用途 |
|----------|------|------|
| **分组注释** | `# ----- 分组名 -----` | 分隔不同配置区域 |
| **说明注释** | `# 说明文字` | 解释配置用途 |
| **警告注释** | `# 【重要】说明` | 强调安全注意事项 |
| **示例注释** | `# 示例: ...` | 提供配置示例 |
| **行内注释** | `VAR=value  # 说明` | 简短说明 |

### 3.3 示例模板

```bash
# ============================================
# CIMF 管理系统配置文件模板
# ============================================

# ----- Django 核心设置 -----
# 【重要】Django 密钥：生产环境必须使用强随机密钥（50+字符）
# 生成命令: python -c "import secrets; print(secrets.token_urlsafe(50))"
# 开发环境可使用默认值，生产环境必须通过此变量设置
DJANGO_SECRET_KEY=your-secret-key-here-change-in-production

# 调试模式：开发环境=True，生产环境=False
DJANGO_DEBUG=True

# 环境标识：development（开发）或 production（生产）
# 生产环境会自动启用所有安全配置
DJANGO_ENV=development

# 允许访问的主机列表（逗号分隔）
# 生产环境示例: yourdomain.com,www.yourdomain.com
DJANGO_ALLOWED_HOSTS=localhost,127.0.0.1

# ----- IP 访问限制 -----
# 是否启用IP限制: true/false
# 不设置 DJANGO_IP_WHITELIST 时，自动从 DJANGO_ALLOWED_HOSTS 提取 IP 地址作为白名单
DJANGO_IP_RESTRICTION_ENABLED=false
# 白名单IP列表，以英文逗号分隔，支持CIDR格式
# 示例: 127.0.0.1,192.168.1.0/24,10.0.0.1
# 留空时自动使用 DJANGO_ALLOWED_HOSTS 中的 IP 地址
DJANGO_IP_WHITELIST=127.0.0.1

# ----- HTTPS/SSL 安全配置（生产环境）-----
# HSTS (HTTP Strict Transport Security) 过期时间（秒）
# 0=禁用, 31536000=1年, 63072000=2年
# 生产环境建议: 31536000（1年）
DJANGO_HSTS_SECONDS=0

# HSTS 是否包含子域名: true/false
DJANGO_HSTS_INCLUDE_SUBDOMAINS=false

# HSTS 是否启用预加载: true/false
# 启用后可在 https://hstspreload.org/ 提交域名
DJANGO_HSTS_PRELOAD=false

# 是否强制 HTTP 重定向到 HTTPS: true/false
# 生产环境必须为 true
DJANGO_SSL_REDIRECT=false

# ----- Cookie 安全配置（生产环境）-----
# Session Cookie 是否仅通过 HTTPS 传输: true/false
# 生产环境必须为 true，防止 Cookie 被窃听
DJANGO_SESSION_COOKIE_SECURE=false

# CSRF Cookie 是否仅通过 HTTPS 传输: true/false
# 生产环境必须为 true
DJANGO_CSRF_COOKIE_SECURE=false

# ----- 数据库配置 -----
# 选择数据库类型: sqlite 或 mysql
# SQLite 自动启用 WAL 模式（通过 Django connection_created 信号），无需额外配置
DJANGO_DB_TYPE=sqlite
# 使用 MySQL 时，取消注释下方配置
# DJANGO_DB_TYPE=mysql
# DJANGO_DB_NAME=cimf
# DJANGO_DB_USER=root
# DJANGO_DB_PASSWORD=
# DJANGO_DB_HOST=localhost
# DJANGO_DB_PORT=3306

# ----- pip 镜像源配置（安装依赖时使用）-----
# 注意：以下仅能有一项处于非注释状态，多项同时启用会导致冲突
PIP_INDEX=https://pypi.tuna.tsinghua.edu.cn/simple
# PIP_INDEX=https://mirrors.aliyun.com/pypi/simple/
# PIP_INDEX=https://pypi.doubanio.com/simple/
# PIP_INDEX=https://pypi.org/simple/
```

## 四、settings.py 读取规范

> 注：数据库配置在 `cimf_django/database.py` 中读取，使用 `DJANGO_DB_*` 系列变量。

### 4.1 读取方法

```python
import os
import secrets
from pathlib import Path
from dotenv import load_dotenv

# 加载环境变量
load_dotenv(Path(__file__).resolve().parent.parent / "config.env")

# 读取配置（带默认值）
DEBUG = os.getenv('DJANGO_DEBUG', 'True').lower() == 'true'

# 读取配置（代码中有默认备用值，非必填）
SECRET_KEY = os.environ.get("DJANGO_SECRET_KEY", secrets.token_urlsafe(50))

# 读取列表类型
ALLOWED_HOSTS_STR = os.getenv('DJANGO_ALLOWED_HOSTS', 'localhost,127.0.0.1')
ALLOWED_HOSTS = [host.strip() for host in ALLOWED_HOSTS_STR.split(',') if host.strip()]
```

### 4.2 类型转换

| 类型 | 方法 | 示例 |
|------|------|------|
| **字符串** | `os.getenv('VAR', 'default')` | `os.getenv('DJANGO_DB_HOST', 'localhost')` |
| **布尔值** | `os.getenv('VAR', 'false').lower() == 'true'` | `DEBUG = ...` |
| **整数** | `int(os.getenv('VAR', '0'))` | `HSTS_SECONDS = ...` |
| **列表** | `os.getenv('VAR', '').split(',')` | `ALLOWED_HOSTS = ...` |

### 4.3 生产环境自动配置

```python
DJANGO_ENV = os.getenv('DJANGO_ENV', 'development')

# 始终启用的安全配置（不区分环境）
CSRF_COOKIE_HTTPONLY = True
SECURE_CONTENT_TYPE_NOSNIFF = True
SECURE_REFERRER_POLICY = "same-origin"

if DJANGO_ENV == 'production':
    # 自动启用安全配置（HTTPS 相关项尊重 DJANGO_* 环境变量，默认 false，
    # 支持无 TLS 终结的单机 http 部署；如有 TLS 再设 DJANGO_SSL_REDIRECT 等为 true）
    DEBUG = False
    
    # 验证必填配置
    if ALLOWED_HOSTS == ['localhost', '127.0.0.1']:
        raise ValueError("生产环境必须在 DJANGO_ALLOWED_HOSTS 中配置实际域名！")
```

## 五、安全规范

### 5.1 敏感信息管理

| 项目 | 规范 |
|------|------|
| **密钥生成** | 使用 `secrets.token_urlsafe(50)` 生成 |
| **密码存储** | 不存储在代码中，仅通过环境变量 |
| **配置文件** | `config.env` 必须加入 `.gitignore` |
| **日志输出** | 禁止在日志中输出 SECRET_KEY、密码等敏感信息 |

### 5.2 Git 管理

**.gitignore 配置：**
```
# 环境变量
config.env
```

## 八、已知问题

### 8.1 `config.env` 中的死配置

`config.env` 文件中存在一行 `SECRET_KEY=...`（无 `DJANGO_` 前缀），该变量名与 Django 和项目代码使用的 `DJANGO_SECRET_KEY` 不一致，实际永远不会被读取，属于死配置。

**建议：**
- 如果作为项目全局唯一密钥用途，应改为 `DJANGO_SECRET_KEY`，覆盖已有的 `DJANGO_SECRET_KEY` 行
- 如果不再需要，直接删除该行

当前 `settings.py` 和 `database.py` 均只读取 `DJANGO_` 前缀的变量，因此 `SECRET_KEY` 无前缀的行不产生任何效果。
