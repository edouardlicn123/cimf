## 3. 模块生命周期 Django 信号

### 方案

为 `Module` 模型添加 4 个信号，用于解耦模块启用/禁用的副作用：

```python
module_installed = Signal()
module_uninstalled = Signal()
module_enabled = Signal()
module_disabled = Signal()
```

### 消费者（潜在）

- **Cron 服务**：模块启用时注册定时任务，禁用时注销
- **缓存刷新**：模块状态变化时刷新动态路由缓存
- **权限预热**：模块启用时缓存权限检查规则
- **WebSocket 通知**：通知在线用户模块状态变化

### 影响范围

| 文件 | 变更 |
|------|------|
| `core/module/models.py` | 新增信号定义 |
| `core/module/services/module_registry_service.py` | 在 `install/uninstall/enable/disable` 方法中发送信号 |
| 新增 `core/module/signals.py` | 可选的信号声明模块 |

### 为何推迟

当前所有消费者（cron、缓存刷新）直接由 `module_registry_service.py` 内联调用，没有解耦需求。在引入第 3 个消费者之前不宜引入信号层。

**触发条件：** 当有第 3 个模块（除 cron、缓存外）需要响应模块状态变化时，优先实施此变更。
