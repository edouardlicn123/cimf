# 客户数据回填计划

> 阶段 5 — 2026-07-08（最后更新：2026-07-08）
> 为导入的客户记录补全 customer_code

---

## 背景

导入引擎绕过服务层，导致导入的客户记录中 `customer_code` 为 NULL（当前）或 `""`（迁移后），而现有 167 条记录的编码格式为 **`cc` + 8位序号**（如 `cc00000001`）。需要为剩余的 3,098 条记录按同一格式补全。

## 影响范围

| 文件 | 变更类型 |
|------|---------|
| `modules/customer/services.py` | 新增 `_generate_unique_code()` 静态方法；所有创建路径统一调用 |
| `core/management/commands/backfill_customer_codes.py` | 依赖服务层的方法，精简实现 |

## 方案

### 编码生成（顺序递增，与服务层共享）

现有编码最大为 `cc00000201`，新编码从 `cc00000202` 开始递增：

```python
@staticmethod
def _generate_unique_code() -> str:
    max_code = CustomerFields.objects.filter(customer_code__startswith="cc").order_by("customer_code").last()
    if max_code:
        next_num = int(max_code.customer_code[2:]) + 1
    else:
        next_num = 1
    return f"cc{next_num:08d}"
```

**为什么不用随机：** 已有 167 条数据使用 `cc`+序号格式，统一风格避免混乱。序号方案天然唯一，无需冲突检测和重试。

### 执行逻辑

```python
def handle(self, *args, **options):
    with concurrent updates blocked:
        for customer in records:
            code = CustomerService._generate_unique_code()
            customer.customer_code = code
            customer.save(update_fields=["customer_code"])
```

### 参数

- `--dry-run`：仅预览受影响记录数，不实际更新

### 风险

- 3,098 条记录逐一 `save(update_fields=["customer_code"])`，无批量更新，但数据量不大、仅单字段写操作，预计 < 5 秒
- 编码生成读取当前最大值，不受记录数影响，O(1)
- 可多次运行，已有编码的记录会被 filter 过滤掉
- **并发安全：** 管理命令单进程运行无竞争；若未来在并发环境调用，需加 `select_for_update` 或悲观锁
