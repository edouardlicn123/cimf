# 导入引擎钩子修复计划

> 阶段 5 — 2026-07-08
> 解决导入绕过模块服务层的架构缺陷

---

## 问题

`ImportService.import_data()` 直接 `model_class.objects.create()`，绕过了模块服务层的业务逻辑（如 `CustomerService.create()` 中的 `customer_code` 自动生成）。所有经过导入的数据都会缺失模块特定的字段补全逻辑。

## 方案：`import_row()` 钩子协议

给导入引擎加一层委托机制，让模块可以选择提供服务层感知的导入方法。

### 接口定义

```python
# 模块服务层（可选实现）
class CustomerService:
    @staticmethod
    def import_row(data: dict, user) -> CustomerFields:
        """导入一行数据，含业务逻辑"""
        customer_code = data.get("customer_code")
        if not customer_code:
            customer_code = "CC" + "".join(random.choices(string.digits, k=6))
        # ... 创建 Node + CustomerFields
        return customer
```

### 发现机制

在 `ImportService` 中新增：

```python
@staticmethod
def _get_import_row(slug: str):
    """尝试获取模块的 import_row 方法"""
    try:
        mod = import_module(f"modules.{slug}.services")
        for attr_name in dir(mod):
            cls = getattr(mod, attr_name)
            if isinstance(cls, type) and hasattr(cls, 'import_row'):
                return cls.import_row
    except (ImportError, ModuleNotFoundError):
        pass
    return None
```

### `import_data()` 中的改动

```python
import_row = cls._get_import_row(node_type_slug)

for idx, row in enumerate(rows, start=1):
    try:
        transformed = cls._transform_row(row, node_type_slug, field_map)
        existing = cls._find_existing(model_class, transformed)

        if existing:
            if skip_duplicates:
                continue
            instance = existing
        elif import_row:
            with transaction.atomic():
                instance = import_row(transformed, user)
        else:
            with transaction.atomic():
                node = Node.objects.create(
                    node_type=node_type, created_by=user, updated_by=user,
                )
                instance = model_class.objects.create(node=node)

        for key, value in transformed.items():
            setattr(instance, key, value)
        instance.save()
        success_count += 1
    ...
```

### `CustomerService.import_row()` 实现

```python
@staticmethod
def import_row(data: dict, user) -> CustomerFields:
    """导入一行客户数据，含 customer_code 自动生成"""
    customer_code = data.get("customer_code")
    if not customer_code:
        customer_code = "CC" + "".join(random.choices(string.digits, k=6))

    node = Node.objects.create(
        node_type=NodeType.objects.get(slug="customer"),
        created_by=user,
        updated_by=user,
    )
    return CustomerFields.objects.create(
        node=node,
        customer_code=customer_code,
    )
```

注意：`import_row` 只负责创建，字段更新由 `import_data()` 中的 `setattr` 循环统一处理。

### 需要改动的文件

| 文件 | 改动 |
|------|------|
| `core/importexport/services/import_service.py` | 新增 `_get_import_row()` + `import_data()` 中增加委托分支 |
| `modules/customer/services.py` | 新增 `import_row()` 静态方法 |

### 向后兼容

- 没有 `import_row()` 的模块 → 保持原有 `model_class.objects.create()` 行为
- 不会破坏现有的导入流程
- 后续新模块只需在 Service 中定义 `import_row()`，导入引擎自动发现

### 注意事项

1. `import_row()` 接收的 `data` 是 `_transform_row()` 处理后的数据（FK 已解析为 ID，boolean 已转换），与 `create()` 接收的视图层 `data` 格式不同
2. `import_row()` 内部需自行创建 `Node`
3. `setattr` 循环在 `import_row()` 返回后执行，会覆盖 `import_row` 中已设置的值——确保 `data` 中已有的字段优先
